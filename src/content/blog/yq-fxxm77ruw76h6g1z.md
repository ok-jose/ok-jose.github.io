## What is VanillaJS? [vəˈnɪlə]
> [看下这个小伙的疑问](https://stackoverflow.com/questions/20435653/what-is-vanillajs)
>

![](/uploads/yuque/fxxm77ruw76h6g1z/1673335351461-c81b950e-65e8-42.png)

总之，Vanilla JS is a joke，就是指原生JS而已，虽然是一个套路，vanilla.js并不是前端社区的恶趣味，相反，它是一个善意的提醒。

-------------------正经的分割线------------------- 

相传vanilla网站的作者是一个前端工程师，老板总是要求他使用JS框架来构建网站，为了坚守自己无框架的原则又要应付上面的要求，他就对老板说，It's running on Vanilla JS ！因为vanilla本身就有”原生“的意思，vanilla JS就是原生JS库的代名词。

于是VanillaJS的故事流传了下来，并被前端社区疯传，它用于提醒世人并不是所有的网页都需要框架，第三方框架的大量引入是网页性能江河日下的罪魁祸首。Vanilla运动希望在现如今js框架如杂草般疯长的乱象中寻找一些可贵的“原生精神”。

但是。。。。

### 初识框架
#### 组件结构
在 Svelte 中，新建 svelte 后缀文件就可以开始编写一个 Svelte 组件了，一个基本的 Svelte 组件包含三大部分：

```html

	let src = '/tutorial/image.gif';
	let valid = true;

{#if valid}
	valid

  {/if}

	img {
		width: 200px;
	}
	p {
		color: red;
	}

```

看下编译后的js、css代码：

```javascript
/* App.svelte generated by Svelte v3.55.1 */
import {
	SvelteComponent,
	attr,
	detach,
	element,
	init,
	insert,
	noop,
	safe_not_equal,
	space,
	src_url_equal
} from "svelte/internal";

function create_if_block(ctx) {
	let p;

	return {
		c() {
			p = element("p");
			p.textContent = "valid";
			attr(p, "class", "svelte-2zzyn4");
		},
		m(target, anchor) {
			insert(target, p, anchor);
		},
		d(detaching) {
			if (detaching) detach(p);
		}
	};
}

function create_fragment(ctx) {
	let img;
	let img_src_value;
	let t;
	let p;
	let if_block = valid && create_if_block(ctx);

	return {
		c() {
			img = element("img");
			t = space();
			p = element("p");
			if (if_block) if_block.c();
			if (!src_url_equal(img.src, img_src_value = src)) attr(img, "src", img_src_value);
			attr(img, "alt", "A man dances.");
			attr(img, "class", "svelte-2zzyn4");
			attr(p, "class", "svelte-2zzyn4");
		},
		m(target, anchor) {
			insert(target, img, anchor);
			insert(target, t, anchor);
			insert(target, p, anchor);
			if (if_block) if_block.m(p, null);
		},
		p: noop,
		i: noop,
		o: noop,
		d(detaching) {
			if (detaching) detach(img);
			if (detaching) detach(t);
			if (detaching) detach(p);
			if (if_block) if_block.d();
		}
	};
}

let src = '/tutorial/image.gif';
let valid = true;

class App extends SvelteComponent {
	constructor(options) {
		super();
		init(this, options, null, create_fragment, safe_not_equal, {});
	}
}

export default App;
```

css 默认是scoped的

```css
img.svelte-2zzyn4{width:200px}p.svelte-2zzyn4{color:red}
```

#### State
在 React 中，组件的 state 需要在编写代码时通过 this.state/setState 或者 useState 来使用；而在 svelte 中，组件的 state 直接使用原始 JS 语法写在 script 标签中即可。也可以认为，在 svelte 组件中，不需要 state，直接使用 js 变量即可；但对变量进行赋值的时候，svelte 会标记组件需要更新，并在 loop 结束的时候，对 DOM 进行更新。

因为没有 VDOM，组件更新时候的时候，svelte 会直接更新变量影响到的 DOM 元素，即对数据和DOM的依赖更新做到了 “Reactive”： UI = f(state)

```html

  let count = 0;
  let label = 'count is '
  
  function handleClick() {
    count = count + 1;
  }

	

{label}

	

{count}

	increment

```

对于上面的例子，当用户点击按钮的时候，svelte 会直接更新第二个 p 元素的 text 元素；而不是重新从模版计算出 DOM 结构进行 Diff 更新。

#### Reactive
在上面的例子中，我们看到了 “state”，并且知道了 state 更新后依赖的 DOM 元素会被 “reactive” 地被更新。svelte 也支持变量直接的 “reactive”，在组件中通过标记语句完成：

```html

	let count = 0;
	$: doubled = count *2;

	function handleClick() {
		count += 1;
	}

	Clicked {count} {count === 1 ? 'time' : 'times'}

{count} doubled is {doubled}

```

svelte reactive 也支持写块语句，类似于 React 中的 useEffect, 当 reactive 语句中依赖的变量变化后，在组件更新后，就会被执行：

```html

	let count = 0;

	function handleClick() {
		count += 1;
	}
  
	$: console.log('the count is ' + count)
  
	$: if (count >= 10) {
	alert('count is dangerously high!');
	count = 9;
}

	Clicked {count} {count === 1 ? 'time' : 'times'}

```

PS: 这里对数组和对象更新要求重新赋值。

#### Props
同样，svelte 组件支持 props，父组件可以通过 props 传递数据给子组件。在组件 script 中的变量加上 export 即可以建变量标记为 props，同样也可以指定默认值：

```html

  // prop name
  export let name;
  // prop age
  export let age = 0;

  

Name: {name}!

{@if age}
	

Age: {age}>

{/if}
```

```html

  import Person from './Person.svelet';

```

#### Lifecycle
svelte 组件的生命周期包括：

+ onMount：组件第一次渲染后的回调
+ onDestory：组件卸载的回调
+ beforeUpdate/afterUpdate：组件DOM元素更新前后的回调
+ tick: tick函数不同于其他生命周期函数，你可以随时调用它，而不用等待组件首次初始化。它返回一个带有resolve方法的 ，每当组件pending状态变化便会立即体现到DOM中 (除非没有pending状态变化)。

#### Store
在 svelte 组件内部，直接通过赋值语句就可以完成对 state 更新，对组件外部的状态管理，svelte 提供了 store，store 的状态可以对多个组件使用和更新；类似于 React 生态的 Redux 等状态管理库。

```javascript
// store.js
import { writable } from 'svelte/store';

export const count = writable(0);
```

```html

	import Incrementer from './Incrementer.svelte';
```

#### Context
svelte 同样提供了 Context，和 React 中的Context 功能基本一致，在祖先组件中 setContext，它的所有下层组件都可以通过 getContext 获取：

```html
// Component.svelte

  import { getContext } from 'svelte'
  const { theme } = getContext('theme');

// Component.svelte

  import { getContext } from 'svelte'
  const { theme } = getContext('theme');

```

## Why Svelte？
整体来说，Svelte 继前端三大框架之后推陈出新，以一种新的思路实现了响应式。

因其起步时间不算很长，国内使用程度仍然偏少，目前来说其生态还不够完备。

  
但这不能掩盖其优势：足够“轻”。因为对于一些通用业务代码来说， **运行时尽可能的小** 和 **框架无关** 是最核心的两个技术选型指标。

Svelte非常适合用来做活动页，因为活动页一般没有很复杂的交互，以渲染和事件绑定为主。一个简单的活动页却要用React那么重的框架多少有点委屈自己。所以对于一些营销团队，想在bundle size上有较大的突破的话，Svelte是绝对可以作为你的备选方案的。

  
另外现在社区对于Svelte还有一个很好的用法是使用它去做Web Component，好处也很明显：

+ 使用框架开发，更容易维护
+ 框架无关，可实现跨框架使用
+ 体积小

就是用来编译可独立分发的 Web Components。传统框架和 Web Components 结合最大的问题就在于运行时：单独分发的 Web Component 里面直接打包框架运行时，等于每个组件都要复制一份框架；不打包的话，又做不到开箱即用。但 Svelte 受这个问题的限制最小（依然存在重复代码问题，但取决于你用了多少功能），可以说是最适合这个用例的框架。

所以对于想实现跨框架组件复用的团队，用Svelte去做Web Component也是一个很好的选择。
